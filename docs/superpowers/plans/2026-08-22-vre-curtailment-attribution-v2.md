# VRE Curtailment Attribution v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace FORCE's one-directional network-curtailment accounting with a versioned, auditable attribution that records economic, forecast/scheduling and redispatch-added/avoided VRE curtailment and exposes it through the modular API and frontend.

**Architecture:** The three existing clears produce a standard VRE counterfactual snapshot. A new independent attribution component applies deterministic copperplate reference allocation, validates the signed identity, and writes period and object rows to market-ledger v6. Version-aware read models, capability declarations and frontend components consume the authoritative result without reconstructing it.

**Tech Stack:** Python 3.10 dataclasses and `sqlite3`; FORCE staged-market contracts and module registry; `unittest`/`pytest`; React 19, TypeScript 5.9, Vinext/Vite; Node test runner and Playwright 1.61.

**Spec:** `docs/superpowers/specs/2026-08-22-vre-curtailment-attribution-v2-design.md`

## Global Constraints

- Do not modify the retained PhD Scheme C source or compatibility runtime; run the existing retained-hash tests after every integration task.
- The public identity is `economic + forecast_added - forecast_avoided + redispatch_added - redispatch_avoided = total`.
- `Redispatch impact` is the public term; do not label it a pure physical-network effect.
- Formal VRE means Solar, Onshore wind and Offshore wind only; hydro spillage, unused imports, storage/network losses and load shedding stay separate.
- Storage charging, export, cross-zone delivery and effective DSR are VRE use, not curtailment.
- Do not add a default GBP valuation for avoided curtailment or alter system-cost, settlement, CEM, storage-cost, hydro, interconnector, DSR or network-physics definitions.
- Use `max(1e-7 MWh, 1e-10 * max(period_realised_available_vre_mwh, 1 MWh))` as the attribution tolerance.
- New runs write `gridform.market-ledger/v6`; completed v4/v5 ledgers remain unmodified and readable.
- Missing or historical avoided-curtailment evidence is unavailable, never numeric zero.
- Keep SQLite batched and frontend detail paginated; add no GIS, Parquet or chart dependency.
- Work only on branch `codex/zonal-redispatch-prompt93-106` in the existing isolated worktree.
