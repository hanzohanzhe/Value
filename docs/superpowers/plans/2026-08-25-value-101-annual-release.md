# VALUE 101 annual teaching release — implementation plan

## Objective

Ship one Windows teaching package with a single CC0 synthetic baseline, two honest execution choices, real research-extension routes, and VALUE-only active product identity.

## Work packages

1. **Execution contract**
   - Replace the old 48-period-per-year `tutorial` policy with a 48-period PSM-only lesson and the existing 17,520-period-per-year two-year policy.
   - Route the one-day lesson through the production PSM without CEM stages.
   - Keep the full two-year route on the production annual PSM–CEM orchestrator.

2. **Teaching data and course**
   - Generate only one deterministic 2025–2026 annual baseline pack (17,520 rows per year).
   - Remove Windy, High-demand and fixed-tariff guided experiments and their comparison dependency.
   - Rewrite Learn around: concepts, one-day market lesson, complete two-year model, and real data/module/domain build routes.

3. **Composer visibility and identity**
   - Keep Basic mode limited to executable system-domain choices and scientifically usable optional domains.
   - Put contract/dependency details in Advanced mode.
   - Rename active runtime IDs, manifests, UI fields, environment variables and packaged examples from FORCE/Scheme C to VALUE; retain historical audit reports outside the active payload.

4. **Documentation and packaging**
   - Rewrite the English guide and quick card from the final UI and execution contract.
   - Update the Windows payload policy, build the installer once, then regenerate the PDF beside it.

5. **Focused acceptance**
   - Check VALUE-only active identity and one annual pack with exactly 17,520 periods per year.
   - Run the one-day PSM-only lesson and verify no CEM calls.
   - Run the complete two-year model and verify 35,040 periods, annual ledgers and the 2025→2026 state transition.
   - Run only affected frontend/build/installer checks, install/reinstall once, and verify the separate main-model directory was not changed.
   - Freeze the John Miles package with SHA-256 values.

## Non-goals

- No scientific-kernel redesign.
- No new solver, transmission method, annual benchmark claim or UK data redistribution.
- No mass rewriting of historical reports, archived prompts or the separately preserved doctoral reproduction model.
- No repeated full test suites or repeated installer builds unless the single allowed installer correction is required.
