# VALUE 第二阶段首批施工记录

日期：2026-10-02。基线：第一阶段提交 `60ee426`。本批交付 2A、2B，以及 2C 的来源和比较入口；完整历史复现与数据包复制、映射增强仍在第二阶段待办中。

## 已交付

首页的 `reproduce from existing data` 和 `add your new data` 进入研究引导。用户选择已保存的基线、为独立副本命名，换数据时明确选择不同的已安装数据包。离开去 Data 安装或校验数据，再返回时保留名称和选择。其余两个社区入口继续保留准确名称和当前能力说明。

服务器提供 `POST /api/projects/{id}/derive`，核对源修订、模块身份和绑定文件校验和，完整复制已保存配置，再生成新的 Study ID。复现保留原数据包；换数据只更换显式选择的基础数据包，沿用方法、参数、年份、扩展、运行选项和求解器契约。网络覆盖包继续服从原配置。服务器记录源 Study、源修订、数据包和模块图，原研究不被覆盖。

保存与运行分离。创建成功后进入 Runs，但不启动计算。新 Study 显示来源版本，并提供基线 Runs 和现有比较入口。比较对象由用户选择，不自动将最新 Run 当作精确基线，也不将多因素差异归因于单一变化。

运行前检查绑定 Study ID、修订、数据包和范围；切换研究或范围后，旧响应不能显示为当前研究的通过状态。保存 Study 时使用显式 ID，修改名称不会误创建另一个研究。普通保存从服务器已有记录继承来源 metadata，不接受客户端伪造来源。

引导页提供“检查 / 更新基线”，打开正确研究的现有编辑器，由用户审阅后保存新版本。失败不会自动升级源研究。Read me 已同步为四步使用说明。

## 真实数据中发现的版本问题

预览环境的旧 VALUE 101 基线缺少后来加入的天气执行身份字段，七个教学模块的源码 SHA 也与当前 registry 不同。派生接口返回 409；这是正确拒绝，不能把当前方法描述为旧方法的精确复现。

验收保留了旧教学 Study 的原始字节，并在本任务的独立预览状态目录中保存一个使用当前方法的新基线。真实 API 分别创建复现副本和换数据副本，均返回 201、独立 ID 和 `run_started:false`。相关科学配置保持一致；已有 Run 数量前后均为 4。三个新建 Study 的名称带“Phase 2 验收”，仅供本地检查。

这里验证当前保存方法的派生闭环；新建普通 Study 的 smoke 不证明客户端可新增教学来源 metadata。完整来源 metadata 保留由派生接口定向测试覆盖。
