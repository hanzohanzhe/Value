## 使用流程

在 `add your new data` 选择基线、填写独立数据包名称，点击复制。服务器将基础数据包复制成新 ID 和独立文件，浏览器直接打开这个目标包。用户选择需求、成本、机组等语义角色，下载模板或上传符合已有契约的文件；校验通过后才更新绑定。页面对照原文件和目标文件的 SHA，并统计新增、改变和缺失角色。仅复制原文件不会显示为已经改变数据。

返回引导时保留研究名称和目标包，再创建新 Study。原 Study、原数据及网络覆盖配置保持原身份。数据副本一旦被当前、回收站或历史不可变 Study 修订引用，服务器拒绝继续替换输入，用户需要再次复制。网络覆盖产品不属于本次复制范围，其安装和管理仍使用 Data Workbench。

本次还修正了数据上下文：引导携带明确的基线 ID、基线修订和目标包 ID，不再进入无关的编辑草稿。基线改变、目标失效、服务离线或页面重载丢失临时引导上下文时，编辑器禁止写入并提示重新选择。角色预览绑定包版本，上传或切换版本后不显示旧预览。

当前提供的是语义角色与标准格式文件的连接，不是任意 CSV 列映射工具。上传后的角色校验与完整研究预检分开，运行仍需用户明确启动。

## 服务接口与数据保护

`GET /api/workspace` 的基础数据包增加当前 `manifest_sha256`；该值与返回的 manifest 来自同一份原始字节，不写回 manifest。

`POST /api/data-packs/{source_id}/clone` 接收 `value.data-pack-clone-request/v1`、名称和源 manifest SHA。服务检查源文件身份与磁盘余量，在包目录之外暂存，验证完成后原子发布新目录。文件独立复制，不共享可写路径或硬链接；路径越界、符号链接、损坏文件和旧 manifest 均被拒绝。来源、授权文件及绑定元数据保留，原包的安装验证标签不冒充副本的验证结果。

`POST /api/data-packs/{id}/files/{role}` 继续复用既有解析和事务校验。克隆包上传必须携带 `X-Expected-Pack-Revision`；服务在锁内重读版本并核对 Study 引用，拒绝并发旧版本和已引用包改写。网络传输在锁外暂存，避免上传期间阻塞其他 Study 操作。

`GET /api/runs/{id}/reproduction-capability` 只读调用现有冻结快照验证器。界面默认折叠，用户点击后才核验。结果说明输入哈希、当前模块身份、对象数量和元数据文件；未完成的检查明确标为未核验。旧响应不能串到另一 Run。

检查通过仅表示保存输入及当前模块身份符合现有验证契约。历史模块源码未随快照打包，完整环境和依赖未固定，便携 Run 包也不含源输入。本批没有实现从历史快照创建全新 Run，也不把检查点存在当作可恢复证明。

现有完成的教学 Run 返回 `verified_recorded_inputs_and_modules`：66 个冻结数据对象和当前模块身份通过既有快照验证，界面正确显示。它是两时段诊断运行；该结果不增加科学验证等级，也不保证完整历史环境可重建。

本批浏览器使用 API 夹具；真实接口证据单独记录。最后只调整了报告信息折叠、按钮样式及隐藏无关草稿选择器，没有重复整套浏览器测试。没有执行全年、十年模型或全仓库测试。
