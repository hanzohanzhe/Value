# VALUE 发布与上传计划

更新日期：2026 年 10 月 4 日。本计划替代此前将 VALUE 与独立站点引擎一同发行，以及采用 APL 或科研评估许可的方案。

本次发行对象为 VALUE 电力系统运行与年度投资模型。软件采用 Apache 2.0，文档采用 CC BY 4.0，三个合成教学与契约包保留 CC0，研究数据按具体对象的许可处理。Electrace 私有差分优化引擎及此前使用的 VALUE-single 名称所指材料，全部排除在 VALUE 发行之外。

## 用户入口与托管

| 位置 | 提供什么 | 当前状态 |
| --- | --- | --- |
| value.ac | 开始使用、安装、数据、方法学和开发导引 | 仅所有者可访问；本轮更新内容，保持现有权限。 |
| GitHub VALUE 源码仓库 | 前后端、模型、SDK、教学包、方法学源稿与网站源码 | 当前仓库私有，作为维护和审阅工作区。 |
| GitHub Releases | 完整安装包、方法学下载包、获准的研究数据包 | 四个 Full 候选与校验文件位于私有草稿 Release。 |
| 数据来源方 | 需要独立获取的原始资料 | 在数据说明中给出来源、条件和重建步骤。 |

普通用户从 value.ac 进入，下载后在本机安装和运行。网站不承担模型求解。大文件通过实际发布的 GitHub Release 地址提供；网站只显示已经存在且可访问的下载。

## 一套源稿对应全部方法学格式

VALUE 方法学修订为 **0.3，2026-10-04**，科学实现与数据依据日期保持 **2026-10-02**。两种语言各九章，依次介绍模型框架、数据、天气出力、运行反馈、全国调度、投资演化、传输约束、完全预见与水文、碳核算。原独立站点引擎章节及相关导读已经排除。

`docs/methodology/zh/` 和 `en/` 为权威正文。`edition.json` 定义共同章序与版本，`scripts/methodology/` 生成文档和公式资源，`website/` 同步生成章节与六个下载文件。各格式经过检查后共同更新，发布清单记录其对应关系。

正文沿用已确认的论文写法：先提出模型设定，再说明数学关系、变量和数据依据；每段推进一个论点；保留影响计算的参数、单位和边界。文件哈希与构建记录放在发行清单中，正文用数据名称和函数名解释计算步骤。

## 代码结构和维护入口

保留 `app/`、`backend/`、`gridform_core/`、`model-sdk/` 等现有路径与运行契约。网站源码以本仓库 `website/` 为准，独立托管工作目录接收受审副本。旧安装目录、科研原件、用户 Study 与 Run、混合方法学和历史包均留在私有工作区。

四类贡献路径及目录职责见[项目结构](REPOSITORY_STRUCTURE.md)。本轮整理文档来源、页面组织与发布检查，模型算法和历史运行结果保持原状。

## 按阶段上传

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 整理内容 | 完成九章方法学、六个下载文件、网页导航、简明 README、目录职责和发布清单 | 双语章序、公式、下载文件和网站链接一致；私有引擎材料排除。 |
| 2 准备干净源码 | 按白名单形成独立源码候选，包含三个 CC0 包和网站；不复制旧 Git 历史或工作目录 | 文件与清单相符；当前缺失依赖有明确记录。 |
| 3 私有同步 | 更新当前私有 GitHub 和私有网站，保留可审阅文档与下载入口 | 远端提交、网站版本和访问权限复核完成。 |
| 4 补齐可运行发行 | 对公开源码的目标功能补齐可分发依赖；确定 Full 候选与源码的对应关系 | 从干净环境完成承诺范围内的最小运行；归档内对象具备相应分发依据。 |
| 5 发行研究数据 | 逐个组装基础包、网络包和冻结复现包，配套来源、许可、依赖与导入说明 | 资产存在、输入依赖完整、版本兼容；相应短案例可导入与执行。 |
| 6 公开上线 | 使用干净 VALUE 快照建立公开历史，发布已满足条件的资产，再开放 value.ac | 用户要求重新公开；公开链接真实可用，旧混合历史继续私有。 |

第 1 至 3 阶段属于本轮整理。第 4、5 阶段按具体软件或数据发行分别推进。源码、Linux 候选和其他平台可分别发布实际达到条件的部分，无需把所有研究案例绑定成一次发行。

当前私有仓库历史仍有旧混合材料，不能直接将整个历史改为公开。先保存私有历史并准备独立候选；正式上线时确定新公开仓库的实际地址，再统一更新 README、引用文件、网站配置与 Release 链接。保持最终原地址需要另行安排私有归档和干净仓库迁移。

## 数据上传安排

三个小型 CC0 包继续随源码管理：`value-101-baseline-v1`、`value-101-network-v1`、`value-synthetic-contract-pack-v1`。Full 候选内置前两个教学包。研究数据使用同一公开 VALUE 项目的独立数据 Release，保持软件与数据版本分别可引用。

| 研究数据 | 组装方式 |
| --- | --- |
| GBP1 国家基础输入 | 先确定完整基础输入和可分发对象，再提供独立数据包。 |
| GBP1 23 区网络 | 记录对基础包的依赖，与兼容的 Study 模板组成套件。 |
| R029 历史全国复现 | 绑定其日历处理、冻结算法与历史参数，单独维护复现身份。 |
| 11 区传输研究 | 保持独立区域、走廊和参数定义，配套自己的输入清单。 |

每份数据资产附带 pack ID、版本、角色与单位、来源、RIGHTS/ATTRIBUTION、兼容模块、缺失输入的合法获取步骤及校验文件。原始天气资料和直接运行输入分别记录。现有前端以数据包或研究套件导入；超过单包能力时，按契约拆成可独立导入的组件，不提供前端无法识别的机械分卷。

## 仅做必要检查

本轮检查发布清单与文件、私有内容排除、双语方法学及文档排版、页面和下载链接、许可范围与版本对应。已有四角色运行验收和 Linux 离线安装记录继续按原适用范围引用，本轮不重跑全年或十年研究。

Windows 和 macOS 的原生验收、签名与公证仍待完成。平台发行应明确实际验证范围；本轮网页和方法学更新不产生新的平台运行结论。

执行顺序和实物对应见[发行映射](release/release-map.json)。构建源码包前运行 `scripts/source_release_scan.py` 与 `scripts/check_publication_scope.py`，正式开放前再核对远端资产和访问状态。
