# VALUE 项目结构

VALUE 将电力系统运行、年度投资和资产演化连接在同一个研究工作区。前端负责配置和解释结果，后台管理研究与运行，模型模块执行计算，数据包提供输入。全国单节点和分区网络是 VALUE 的不同研究配置。

## 按任务找入口

| 你要做什么 | 主要目录 | 使用方式 |
| --- | --- | --- |
| reproduce from existing data | `data-packs/`、`docs/tutorial/` | 选择兼容的数据与模块，建立 Study，检查输入后运行。 |
| add your new data | `gridform_core/data_workbench/`、数据契约、`app/features/data/` | 映射字段、时间与单位，生成独立数据包，再绑定到 Study。 |
| Edit module | `model-sdk/`、`examples/`、模块注册表 | 为已有计算环节实现新模块，使用独立 ID 和版本。 |
| add new function to VALUE | `model-sdk/`、扩展契约、`backend/`、`app/` | 先定义输入、输出和生命周期位置，再接入后台与界面。 |

四类操作的入口见[用户导引](../README_BILINGUAL.md)与[模块开发导引](MODULE_DEVELOPER_101_ZH.md)。研究结果记录所用模块、数据和参数；配置变更形成新的研究修订。

## 目录职责

| 目录 | 职责 | 维护边界 |
| --- | --- | --- |
| `app/` | 本地模型前端与四类用户工作流 | 展示、输入和操作指引；科学计算通过后台接口调用。 |
| `backend/` | API、工作区、任务和运行管理 | 校验请求，管理 Study、Run、数据包与模块。 |
| `gridform_core/` | 年度计算、调度、投资、网络、核算及数据契约 | 保持科学单位、状态传递和模块契约明确。 |
| `gridform_validation/`、`tests/`、`e2e/` | 科学检查、接口检查与用户任务验收 | 根据改动选择必要检查。 |
| `model-sdk/`、`examples/` | 外部模块和扩展开发接口 | 新实现使用独立身份，按声明的契约接入。 |
| `data-packs/` | 三个可分发的 CC0 合成包 | 保留包身份、单位、生成关系和各包许可。 |
| `docs/methodology/` | VALUE 中英文方法学源稿及版本定义 | 先修改源稿，再生成网页、Word、PDF 和离线 HTML。 |
| `scripts/methodology/` | 方法学组装和文档生成 | 生成中间文件写到构建目录，不修改科学源数据。 |
| `website/` | value.ac 的静态页面、方法学展示和下载指引 | 部署生成的 `dist/`；模型求解在用户本机进行。 |
| `packaging/`、`requirements/` | 安装器、运行时和依赖锁 | 安装包按自身构建版本和校验清单发布。 |
| `scripts/` | 构建、数据准备与发布核对 | 发布范围由清单限定。 |

运行链为“前端配置 → 后台冻结研究输入 → 模块注册与年度计算 → 结果存储 → 前端解释”。官网是使用与文档入口，本地前端是建模工作区，两者分别构建和部署。

## 方法学的维护方式

`docs/methodology/zh/` 与 `en/` 保存对应的九章正文，`edition.json` 记录章序、编辑日期和科学依据日期。生成器使用同一章序制作各格式，网页从生成结果同步内容和公式资源。公式、参数和数据名称在源稿中修订，下载文件随版本重新生成。

本次整理保留既有运行目录和导入路径。`gridform_core`、`force.*`、`gridform.*` 等兼容标识继续服务已有 Study、数据和外部模块；名称迁移另行使用版本化兼容方案。

## 源码和数据的发布边界

当前源码审阅快照包含前后端、模型代码、SDK 和三个合成包。真实研究输入、部分碳因子与研究储能参数保留独立分发边界；干净克隆运行仍需完成对应依赖整理。完整安装包使用自身清单与验收记录，不能由源码目录的存在推断其可用性。

软件许可、数据许可和文档许可见 [LICENSING.md](../LICENSING.md)。具体上传顺序与完成条件见[发布计划](PUBLICATION_PLAN.md)。
