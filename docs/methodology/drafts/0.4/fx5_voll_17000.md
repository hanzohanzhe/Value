# Value of lost load: 17,000 GBP/MWh in both profiles (FX5 draft for methodology 0.4)

Status: draft written with construction unit FX5 (2026-10-06), following decision
A16-5 of `docs/dev/P0_DECISIONS.md`. It supersedes the VoLL statements of
`p06_default_psm_clearing.md` (now edited to match) and lists the 0.3 sentences
that the 0.4 edition must replace. The 0.3 sources (`en/`, `zh/`) stay frozen
until the 0.4 edition is generated and reviewed (plan C26).

## 1 The rule

The value of lost load (VoLL) is **17,000 GBP/MWh**, the author's value. On the
half-hour clock that is 8,500 GBP per MW of unserved demand and period
(17,000 x 0.5 h). It applies to both methodology profiles:

| Where VoLL enters | Doctoral reproduction (`doctoral-lineage-0.6.0a2`) | Corrected (`value-corrected`, default) |
|---|---|---|
| Default PSM physical operating cost: recorded blackout x VoLL (`physical_operating_cost_detail_gbp.blackout_reliability`) | constant 17,000 (`reliability_voll = constant_17000`); the parameter is ignored | `market.voll_gbp_per_mwh`, default 17,000 |
| Thesis-code cost history (`runtime_compat/case3.py`, `modular_case3.py`: `Lost_Value_of_Electricity_GBP`, `Total_System_Cost_GBP`) and the original-thesis system-cost view (`doctoral_ledgers.build_system_cost_views`) | 17,000 | 17,000 |
| Perfect-foresight LP (shedding priced in the objective and the system cost) | `market.voll_gbp_per_mwh`, default 17,000 | same |
| Reference DC network, doctoral national PSM | `market.voll_gbp_per_mwh`, default 17,000 | same |
| Staged chronology: copperplate balancing (an up bid above VoLL is never accepted) and zonal redispatch (VoLL x shed in the primary objective, the network-free counterfactual and the redispatch accounting) | network modules run only under the corrected profile (Q3) | `market.voll_gbp_per_mwh`, default 17,000 (the VALUE UK study already pinned 17,000) |

Before A16-5 the thesis code valued deficit energy at 8,000 GBP/MWh and the
parameter registry defaulted to 10,000 GBP/MWh. In the default PSM and in the
thesis-code cost history VoLL enters **only the cost accounts**: it never
changes dispatch, prices, storage state or investment. Replacing the thesis
constant is therefore a universal accounting correction (Q12, correction id
`fx5.voll-17000`); the doctoral trajectory stays bit-identical. In the
perfect-foresight LP, the DC network and zonal redispatch VoLL is an objective
coefficient, so a Study that relied on the old default may also dispatch
differently (version bumps with explicit confirmation, Q13).

A Study can still set `market.voll_gbp_per_mwh` explicitly (0-1,000,000
GBP/MWh); that value is used by every module that reads the parameter, except
the doctoral rule set of the default PSM, which keeps its constant.

## 3 Numbers

None of the golden cases records blackout: VALUE 101 smoke, two_year_smoke,
value_101_day and two_year in both profiles (D1-D4, C1-C6), the staged
copperplate and zonal cases (C7, C8) and the GBP1 first model year in the
doctoral profile (D5). Their headline system cost is therefore unchanged;
only the VoLL value (8000 or 10000 -> 17000) and its basis label in
`physical_operating_cost_detail_gbp` change. VALUE 101 two_year headline
system cost: doctoral 29.062 GBP m (2025 14.627 + 2026 14.435), corrected
legacy storage 29.158 GBP m, corrected dynamic storage 29.257 GBP m, all
unchanged. The hidden shortfalls of decision A2 (stress events) are reported
in MWh and are not valued at VoLL in any headline. Details:
`docs/dev/p0-reports/FX5-VoLL-17000.md`.
