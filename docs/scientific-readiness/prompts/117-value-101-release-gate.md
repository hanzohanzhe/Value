# Prompt 117 — VALUE 101 release gate and clean-user rehearsal

## Purpose

Decide whether the self-contained Windows package produced by Prompt 116 may
be sent to a first external teaching tester. This is a fail-closed release gate
for the bounded VALUE 101 journey. It does not certify annual British results,
the retained Scheme C baseline, or a ten-year VALUE scientific pathway.

## Reused contracts

This prompt does not add another solver, teaching runtime, comparison formula,
data format or reset path. It audits the Prompt 109–116 product and reuses:

- the real registered PSM–CEM execution chain;
- the three controlled ordinary teaching packs and optional fixed-network pack;
- immutable Study revisions, run artifacts and server-owned comparison output;
- metadata-scoped completion/reset behavior;
- the current-user offline installer and its private runtimes.

## Machine-readable gate

`scripts/audit_value_101_release.py` is the release decision authority. Its JSON
report checks:

- source commit and explicitly allowed evidence-only dirty paths;
- installer presence, minimum self-contained size and SHA-256 sidecar;
- exact embedded payload hashes plus an independently source-controlled private-runtime inventory digest;
- Windows product contract, documentation and progress-window sources;
- all four CC0 pack identities, bindings and file hashes;
- absence of the internal AC experiment from the ordinary module catalogue;
- explicit non-annual teaching labels;
- the exact one-dimensional baseline/data/storage comparison contract;
- reconciled network energy, SOC, corridor, curtailment and cost identities;
- immutable SQLite network evidence with no live WAL or shared-memory sidecar;
- installed API routes, safe reset/isolation and retained Scheme C hashes;
- Python/frontend verification evidence;
- completion of the first seven user steps within 30 minutes and without
  developer intervention.

The Markdown report only renders the machine-readable result. It must never
silently repair, reinterpret or recalculate failed evidence.

## Clean-user route

The rehearsal starts from an empty VALUE 101 teaching state and follows the
same route that will be given to John Miles:

1. install and open without a terminal;
2. read the five building blocks;
3. create and run Baseline;
4. preview, create and run Windy or High demand;
5. preview, create and run Legacy storage pricing;
6. compare the three rows and open stored evidence;
7. open **Build from VALUE 101** and identify data, module and year layers;
8. optionally run the matched copperplate/network lesson;
9. export the completion report;
10. reset teaching state and verify unrelated state remains unchanged.

Timestamps, mistakes and interventions are evidence. They are not edited after
the rehearsal to make the route appear easier.

## Failure codes

The gate fails closed for an incomplete or mismatched installer, missing
product files, invalid or corrupt teaching packs, exposed AC experiments,
annualised teaching claims, uncontrolled comparison dimensions, unreconciled
network ledgers, failed installed routes, unsafe reset, changed retained source,
incomplete software tests or a failed/over-30-minute clean-user journey.

## Release boundary

A passing result authorises distribution of `VALUE-101-Setup.exe` as a bounded
Windows teaching pilot. It does not authorise describing VALUE 1.1 as a newly
validated UK annual or ten-year scientific baseline.
