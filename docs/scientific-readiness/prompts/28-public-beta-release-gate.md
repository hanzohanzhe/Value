# Prompt 28 — Integrated public-beta release gate

Execute only after Prompts 11-27 are individually accepted. Read their deliverables
and `RELEASE_GAP_MATRIX.md`. Act as the independent release owner. Add no new model
features in this task.

## Objective

Verify that scientific semantics, real module execution, immutable inputs,
data adapters, uncertainty handling, lifecycle controls, UX, packaging,
documentation and publication rights work together. Return an evidence-backed
public-beta GO/NO-GO decision.

## Mandatory constraints

- Preserve retained Scheme C sources, authoritative fixture, installed data pack,
  historical outputs and completed Prompt 10 runs byte-for-byte.
- Never alter a baseline, tolerance or scientific definition merely to pass.
- Do not launch expensive annual runs until unit, contract, synthetic E2E and
  preflight gates pass and disk/runtime estimates are accepted.
- Public-code GO and UK-data redistribution GO are separate decisions.

## Gate sequence

1. Verify the repository rights inventory and release allowlist. Stop before
   packaging if required code rights are unresolved.
2. From a clean locked environment, run retained-source hashes, static/type checks,
   unit/contract tests, module conformance, adapter tests, independent PSM oracle,
   cost/carbon reconciliation, planning/terminal invariants, security/bundle tests,
   frontend build and real browser E2E.
3. Run the synthetic two-period and two-year workflows through the packaged local
   website/application service, including one external module replacement,
   cancellation/resume and bundle validation.
4. Run one full 17,520-period year for both dynamic and legacy storage policies.
   Publish economics only if scientific, cost, carbon and energy gates pass.
5. After recording estimates/free disk, run immutable 2025-2034 dynamic and
   legacy-tariff projects through the real modular path. Do not overwrite earlier
   runs. Use declared terminal treatment and record runtime/artifact size.
6. Compare both new runs with the retained 2026-07-18 Scheme C result using named
   definitions. Separate architecture parity, legacy metric parity and scientific
   interpretation; never call the modular legacy policy an exact reproduction
   unless it satisfies the declared gate.
7. Run the bounded storage-floor sensitivity and at least the minimum accepted
   planning/weather ensemble needed by Prompts 16, 18 and 20. Label limited sample
   evidence exploratory where required.
8. Validate exported bundles, scenario-comparison UI, mathematical reference,
   installation instructions, package contents, SBOM and absence of prohibited
   data/absolute paths/secrets.
9. Produce one versioned release report with every gate status, command, environment,
   revision/hash, duration, bytes, tolerance, artifact link and unresolved risk.
10. Simulate the documented contributor/programmer flow from a clean checkout:
    create the locked environment, run the doctor, build frontend/backend, install
    the synthetic data pack, register one external data adapter and one external
    module through public contracts, create a project, run it, inspect/export the
    result, restart and resume/import it. Use no developer Desktop files or hidden
    local state.
11. Execute the release tests in three explicit tiers, stopping on the first failed
    prerequisite:

    - `short`: analytical/unit/contract tests plus 2-, 24- and 168-period synthetic
      PSM/CEM cases for every built-in formulation and storage-policy capability;
    - `two_year_full`: 17,520 periods for 2025, the complete investment/caps/
      planning/state transition, then 17,520 periods for 2026. Run at least the
      published dynamic/current-carbon baseline and legacy-tariff/Scheme-C-carbon
      reproduction project through the website worker;
    - `ten_year_full`: immutable 2025-2034 runs (175,200 half-hours each) for those
      two canonical projects, followed by comparison with the retained Scheme C
      result. A user/external module that claims annual scientific readiness must
      pass short and two-year gates; include it in the ten-year matrix before
      publishing equivalent long-horizon claims.

    Record wall time, peak memory, disk growth, solver/runtime versions, run IDs,
    snapshots and hashes. A smoke/short result can never satisfy a full-year gate.

## Tests and acceptance

- Every Prompt 11-27 acceptance result is linked to immutable evidence.
- Website-selected modules are proven to execute; no replay or silent fallback is
  reachable from production.
- Published costs and carbon reconcile and state their denominators.
- Run inputs and resumed checkpoints match frozen revisions.
- Synthetic installation/E2E works for a non-programmer on the supported platform.
- Public artifacts contain no restricted UK data unless redistribution permission
  is explicitly evidenced.
- Known limitations are visible in README, model reference and UI.
- Short, two-year-full and ten-year-full reports reconcile CEM system cost and the
  selected carbon-factor scenario, and the frontend comparison reproduces their
  backend summaries exactly.

## Stop condition

Stop at the first failed preservation, legal, security, cost/carbon reconciliation,
real-module-execution or immutable-input gate. Do not spend hours on ten-year runs
to compensate for a failed prerequisite; issue a `NO-GO` with the smallest safe
next task.

## Release decision

Return separate decisions:

- `PUBLIC_CODE_BETA_GO` or `PUBLIC_CODE_BETA_NO_GO`;
- `UK_DATA_DISTRIBUTION_GO` or `UK_DATA_DISTRIBUTION_NO_GO`;
- `SCIENTIFIC_BASELINE_GO` or `SCIENTIFIC_BASELINE_NO_GO`.

For every NO-GO, identify the first failing gate, evidence and smallest safe next
task. A successful process exit or attractive chart is not a release gate.

## Deliverable

Provide the signed/versioned release report, test and experiment matrix, two
ten-year bundle IDs, retained comparison, installation evidence, publication
allowlist and the three explicit decisions.
