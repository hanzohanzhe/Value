# Prompt 43 — CEM parity or declared divergence

Continue after Prompt 42. This prompt resolves the scientific identity of the
public typed CEM; it does not alter the retained Scheme C implementation.

## Objective

Either prove that the public CEM is a faithful modular extraction of retained
Scheme C, or explicitly declare and name every intentional difference as a new
FORCE CEM formulation.

## Required comparison

- Extract read-only decision traces for the retained investment, support-income,
  operational-income, payback/`Invest_Profit`, cap, pipeline and commissioning
  rules.
- Cover REPD filtering, zombie-project treatment, spatial assignment,
  technology aggregation, project success, construction stages, storage and
  wind/solar caps, and exogenous pumped-hydro planning.
- Feed identical frozen inputs, seeds and annual PSM summaries to retained and
  typed paths, then compare decisions at every rule boundary.
- Classify each mismatch as an implementation defect, intentional new scientific
  assumption, or unavoidable information-structure difference. Never label a
  divergent model a Scheme C reproduction.

## Acceptance

- The payback investment branch and all retained eligibility filters have either
  executable parity tests or an explicit versioned replacement specification.
- A machine-readable decision matrix identifies inputs, equations, output fields,
  tolerances and parity status for each CEM stage.
- Frontend, README and model card show the selected CEM identity and differences.
- At least two annual transition fixtures cover investment accepted/rejected,
  pipeline success/failure and commissioning.

## Stop condition

Do not publish a retained-comparison claim while any material mismatch is merely
hidden behind a common module name.
