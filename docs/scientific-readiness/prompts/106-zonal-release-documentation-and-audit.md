# Prompt 106 — Zonal documentation, packaging and release audit

Execute after Prompt 105, or earlier only as a clearly labelled documentation
preview. Act as release architect, scientific reviewer and novice-user editor.
Do not claim that an unexecuted or failed validation gate passed.

## Objective

Package the optional fixed-network feature as an honest, reproducible research
capability while preserving the copperplate teaching path and the retained
Scheme C reproduction model.

## Documentation

Update English and Chinese material to explain:

- national ahead clearing followed by replaceable balancing;
- thesis-compatible copperplate versus optional zonal transport redispatch;
- zone, computational corridor and ETYS cut-set meanings;
- spatial allocation, two weather modes, offshore inference and fallback node;
- pay-as-bid redispatch cashflow, six ledger identities and counterfactual cost
  decomposition;
- observed reliability metrics, lossless fixed network and unsupported scope:
  no AC feasibility, N-1/security claim, real-line-flow claim or endogenous
  transmission expansion;
- how to provide a compatible signed network pack or balancing module;
- how to interpret, export, replay and compare network results and solver failure.

Keep Castle 101 and copperplate as the first 30-minute path. Put zonal network
work in an advanced optional chapter. Apply the repository's humanisation review
to prose without changing scientific meaning.

## Packaging and release audit

1. Include code, schemas, synthetic zonal fixture, migrations, frontend and test
   assets in the source release.
2. Treat the real GB signed network/data pack as its own rights-governed asset;
   verify provenance and redistribution for every source object.
3. Prove clean installation, pack validation, frontend build, synthetic run and
   independent solver gate from a fresh clone on supported Python/Node versions.
4. Recheck retained Scheme C hashes, public module manifests, schema examples,
   prompt index, generated-document consistency and absence of local paths,
   secrets, caches or run outputs.
5. Confirm that no bundled selectable transmission-expansion implementation
   appears in this release line.

## Decision

Publish a machine-readable and human report with separate decisions for:

- copperplate teaching/research beta;
- optional fixed-network zonal redispatch;
- scientific benchmark status of the signed GB pack;
- redistribution status of each data product;
- unsupported experimental DC/AC/expansion capabilities.

## Acceptance

- A novice can complete Castle 101 without encountering network configuration.
- An advanced user can reproduce a signed-pack network run and inspect one
  period's bids, transfers, payments and curtailment.
- All documentation terms match schemas and UI labels.
- Release claims follow executed evidence and all blocking gates are explicit.

## Deliverables

- bilingual handbook, methodology and module/data-pack extension guide;
- clean-clone/release audit evidence and release manifest;
- final Markdown/JSON readiness decision.
