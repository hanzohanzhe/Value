## Purpose

Prompts 65–70 created real extension, hydrology, network, DC, experimental AC
and transmission-expansion contracts. Prompt 71 accepted those capabilities at
different maturity levels. Prompts 77–83 now expose the same registry graph in
the ordinary browser through capability-led Studies, conditional Data roles,
extension lifecycle, domain preflight and artifact-backed result queries.

This sequence closes that user-facing composition gap. It does not reimplement
any solver, hydrology equation, investment rule, data-bundle transaction,
module-bundle installer, market replay or VRE-curtailment calculation already
delivered by Prompts 56–70.

## Expected product outcome

A non-programmer should be able to create a Study by answering four questions:

1. Which system domain is being modelled: single node, DC network or
   experimental AC feasibility?
2. Which optional domains are active: hydrology and/or transmission expansion?
3. Does the selected data pack satisfy the resulting conditional input
   contract?
4. Are the selected methods ready, experimental or not evaluated for the
   intended chronology?

The saved revision must contain exactly the module map, selected extensions,
extension parameters, data bindings and maturity acknowledgements shown by the
browser. Preflight, snapshots, checkpoints, result provenance and comparison
must resolve the same graph hash.
