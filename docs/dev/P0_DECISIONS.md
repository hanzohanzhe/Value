## 作者对建模问题的澄清（第二轮，优先于上文）
| # | 发现 | 决策 |
|---|---|---|
| A1 | P6-08 风电出力偏高 | 作者确认偏高。只在修正口径中，在 ERA5→功率曲线之后加文献损耗系数（同 Q15），论文对齐口径不动。 |
| A2 | P3-01 缺电被隐藏 | **不改调度**（出力、电价不变）。凡是供给小于需求的时段，两个口径都记录 **stress event**：逐期缺口（MWh）、持续时段数；年度结果汇总事件次数、时段数和总缺口；能量平衡账中缺口计入“缺电量”一项。P0-6 原计划中改出清逻辑的部分取消。 |
| A3 | P6-24 互联线序列被拉伸 2 倍 | 两个口径都改为与 17520 期逐期对齐（同 Q9）。 |
| A4 | P4-01 投资用毛收入 | **风电、光伏、储能的毛收入即利润是论文设定**：它们只有 CAPEX 和折旧，没有 OPEX，原代码中 VRE 的 gen_cost=0.0001，储能不计运营成本。**不是错误，不改**。原 Scheme C 对**火电**（燃气、生物质）按“收入 − 发电量 × gen_cost（含燃料、碳价、单位时间成本）”计算净收入（`runtime_compat/modular_investment_support.py:2150-2152, 2247`），v2 移植时（`v2_module_definitions.py:153`）丢掉了这一项。作者决定：**两个口径都恢复火电的扣减**，这是 Q1 严格冻结的第二个例外，复现基准相应一次性重基线并附差异报告。今后为风光增加 OPEX 属于新功能，不在本轮。审查报告中 P4-01 的表述需按此更正：问题只限于火电。 |
| A5 | P6-02/P6-03/P6-04 GBP1 互联线与需求读取（比利时 EUR 逐小时被当作 GBP 半小时、BE/NL 潮流文件对调、2022-10-30 DST 后需求错位 1 小时） | **两个口径都修**，视为数据读取的软件错误；复现基准对应部分一次性重基线并附差异报告。这是 Q1 严格冻结的第三个例外。 |
| A6 | P4-02 投资判据（ROI > preferred_rate 或回收期 ≤ 目标年限，会接受 NPV<0 的项目） | **不是错误，两个口径都保留现规则。** 作者说明：模型所有金额均以起始年币值计价，未来收入与现在等价，因此不做折现。P4-02 从修复范围中移除，改为在方法学文档中写明这一设定（不折现的投资决策规则）。修正口径**不改为 NPV**。 |
