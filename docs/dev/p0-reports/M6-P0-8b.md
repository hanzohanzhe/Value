## 5 偏差

1. **参数类型**：计划中的两个“按技术”参数需要映射类型，而参数注册表只支持标量。按保守做法实现为 JSON 对象字符串参数（`"{}"`、`'{"nuclear":100.0}'`），解析时校验（非对象、负值、非有限数都拒绝）。界面上它们只是高级文本参数；若作者希望有专门的表格控件，需要设计方另定。
2. **copperplate 的 scientific_version 未改**：doctoral 口径白名单列出了 `value-copperplate-balancing-2026.08.21`（没有 doctoral PSM 调用 balancing 槽，Q3），改动它会让 doctoral Study 被拒。只升版本号 1.1.0 并标 opt-in；staged 的 scientific_version 已更新。
3. **单价表与 runtime state**：C22 要求不再改 runtime state schema，agent 运行成本因此借用 `zonal_account_totals_gbp` 自由映射（带前缀的键）跨 checkpoint 累计，字段和 schema_version 都不变。
4. **耗时验收**：validation_168h 需要研究数据包，本机只有教学包，且教学包不允许该模式；改用 VALUE 101 network value_101_day 端到端测量（9.2 s → 10.4 s）。每期新增两次无网络 LP（各四阶段），GB 规模的绝对耗时仍需在有研究包的机器上实测。
5. **没有单独的 `GF_METHOD_RULE_CHANGED` 预检码**：X0 S11 已落地，方法变化由 VERSION_LEDGER 的 `requires_user_opt_in=true` 驱动 `method_upgrade_required`（Q13）；staged 1.3.0、copperplate 1.1.0 都标了 true。
6. **账本列**：评审建议的 `perfect_forecast_blackout_mwh` 等新列需要改 DDL，计划要求账本 v8 不改 DDL，故未加；各情形的缺电量已经以 VOLL 计入情形成本。边界值仍是一列（正向取符号），状态写在语义串里。
7. **（已被第 8 节取代）PH/H2 储能与 merchant 风电同为 £0 dec**：原文称“电池严格先充电后弃风”，这一说法不成立——只要当期存在 £0 的 VRE 上调 bid，电池的 dec 价同样被封顶为 0，与风电打平后被排在发电之后。评审回应中已改为按共享类别次序处理，电池、抽蓄、氢储能在同价时都先充电后弃风。
8. **degenerate_dual 的判断基于 primary 解**：后续阶段可能把潮流移开（VALUE 101 的 CS 边界在 primary 满载、最终利用率 0.31），所以报告中的利用率与状态可能看起来不一致；含义已在文档中写明。
