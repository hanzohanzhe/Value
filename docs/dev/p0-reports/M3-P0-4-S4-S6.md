## 2 实现要点

### 2.1 S4 逐资产储能审计（P3-14、P5-11）

- 新模块 `gridform_core/builtin/scheme_c_1000twh/native_balance_audit.py`（runtime_compat 之外）：`StorageEnergyAudit` 按期累加，审计对象挂在电池 `__dict__` 上惰性创建，因此 `Battery.__new__`（module_conformance）构造的对象同样可用。
- 内核（只读、轨迹零变化）：`Battery.charge` 记入网侧充电与储存侧增量；`discharge` 记入网侧放电与取出的储存量；`clr_stored_energy_var(key, value, audit_period=None)` 在删除 <0.001 的尾量时记为尾量注销；新增 `apply_self_discharge(period)`（内部仍调用同一个 `decay_func`，逐位相同，记录衰减量）；`cleanup_negligible_energy` 同样记账。ahead 市场的衰减调用改为优先调用 `apply_self_discharge`。每期开始以期初 SoC 打开审计，期末与 `storage_state` 同处写出审计行。
- 账本：可选表**首次写入时才建表**，其他 PSM 的账本表集合不变。`storage_energy_audit` 每行带 SoC 恒等式残差（VALUE 101 上 ≤2e-15）；`storage_year_boundary` 记录每年期初/期末 SoC 与默认 PSM 每年新建电池而丢弃的期末存量（`carry_policy=new_battery_each_year`，只记账不改行为）。`_close_legacy` 用 SQL 按年汇总（默认 PSM 每年新开一个账本实例），另给只报告的吞吐越界计数。
- 原生 PSM 在 `run_simulation` 前后记录各电池期初/期末 SoC，写入年边界表。

### 2.2 S5 按来源分类的盈余去向（Q7）

- 内核模块级 `_SURPLUS_TRACE`：ahead 市场结束后，按 `excess_energy_list` 的资产类型判定盈余来源（核电必发 → `in_dispatch`，未被接纳的 VRE → `out_of_dispatch`；ahead 市场在边际报价处停止，因此只有一个来源）。在各取用点（储能、出口、电解、平衡阶段回用、削减）读取内核自己的 `excess_energy`/`need_curtailed_energy` 前后差值。削减分支中“预测−实际”的盈余属于调度内（已在 S 中）。
- 每期按来源写一行 `surplus_routing`：available = 储能 + 出口 + 电解 + 回用(to_dispatch) + 削减(curtailed，真正移出 S 的部分) + spilled + unrealised。
- **W_in（non_vre_spill）**：内核“声称”的调度内弃置量 = 未用掉的调度内盈余 + 已记削减但未从 S 移出的部分；W_in 取该声称量与节点实际未用供给 `max(0, S+B+U_out−D−C−E−X)` 的较小者，差额记为 `unrealised`（内核分配了 S 中并不存在的盈余，即 P3-01）。该上限只会让 W_in 变小，所以缺电和重复计入永远留在残差里。
- 调度内盈余的“回用”就是 DEV-BAL-04 的重复计入，单列为 `non_vre_double_counted`。
- `RealisationLog.record_surplus` 保存节点项（不在 P0-6 的 LOG_COLUMNS 中）。契约中 `SurplusRoutingRow` 增加三个可选列（缺省 0），oracle 读取时缺列按 0 处理，S1 的手算用例不变。

### 2.3 S6 声明边界、受限兼容调整与 A2 stress（P7-10、P3-02、A2、C19）

- 契约：`RULE_SET_BOUNDARIES`/`boundary_for_rule_set`（doctoral 规则集 `native-doctoral-thesis-v1` → `default_psm_surplus_node_v1`，corrected 规则集 `native-corrected-v1` → `native_corrected_full_node_v1`，部分规则集不声明）；`boundary_shortfall`、`balance_booking`（缺口作为“缺电量”记入：closing = raw − B + shortfall）、`capped_adjustment`（只在 1e-9 < |raw| ≤ 容差时取 −raw）。doctoral 注册表条目加入 doctoral 规则集 id。
- 内核在 `run_simulation` 开头（取得 active ledger 后）按规则集声明边界，也覆盖 ReferenceSchemeCPSMBridge；每期原始残差按声明边界和 S5 的 U_out/W_in 计算，兼容调整受上限约束，并在 `record_period` 之前写 `BalanceTermsRow`。未声明边界的调用方保持原有自报与闭合规则。
- 账本：`declare_balance_boundary`（元数据 `energy_balance_boundary`/`energy_balance_rule_set`，同一账本不得更换边界）。已声明时 `record_period`：自报 raw 与重算不一致 → `GF_LEDGER_RESIDUAL_SELF_INCONSISTENT`；|adj| 超上限 → `GF_COMPAT_ADJUSTMENT_ABOVE_CAP`；缺少边界项 → `GF_LEDGER_BALANCE_TERMS_MISSING`；物理不平衡只计数，`strict` 时抛 `GF_ENERGY_BALANCE_STRICT`。逐期写 `balance_boundary_period`（U_out、non_vre_spill、double count、unrealised、raw、adj、shortfall、hidden unserved、closing、stress_flag）；关闭时用契约的 `stress_events` 按年分组写 `stress_event`，并在 `metadata.json` 的 `energy_balance.by_year` 中给出事件数、stress 时段、总缺口等年度汇总。`validate_market_ledger_file` 新增 `physically_consistent`/`physically_inconsistent_periods`（无声明边界时为 None）。
- 原生 PSM：`physical_dispatch` 的行集、能量和 scope 文案保持 HEAD（这些列属 trajectory 区）；只改 accounting 列 `balance_component_mwh`：负荷分量 = −负荷 + 喂给它的 U_out，W_in 记在 excess 行与削减行上，于是“分量之和 − 需求 = 声明边界 raw”。`runtime.energy_balance_strict` 经环境变量 `ENERGY_BALANCE_STRICT` 传入内核。
- 版本：`value-bid-at-cost-psm` 5.1.0 → 5.2.0（台账登记三个 correction id，`requires_user_opt_in=false`，只影响 accounting/identity）；`execution_identity` 依赖加入 `energy_balance_contract.py`。

## 6 偏差

1. **`storage_state.charge_mwh` 未改**。计划 S4 的验收是“golden 中只有这一列变化”，但 X0 golden 把它钉为 trajectory，doctoral 重基线名单也没有 P3-14（M0-P0-6-S1 报告已提交给 lead，仍未决）。按保守原则保留 HEAD 的 0.0，逐资产充电记在新的 accounting 表 `storage_energy_audit` 中（Σ = 11.113 MWh）。若 lead 批准该列改区，可在一个小提交中把审计值写回该列。
2. **版本只升一次，放在 S6 提交**（计划写在 S4），台账登记三个 correction id。
3. **correction id 不写入 `corrections/p04.json`**：三者都是通用（universal）的账目修正，沿用 `p04.validation-v2` 的先例；写入目录会改变两个口径的 applied-corrections 哈希，引发 Study 迁移确认，而本次没有方法变化。代价是旧 Run 没有“未应用该修正”的逐条 advisory（旧 Run 的能量平衡已由读时 oracle 标注）。
4. **C6（nightly）只在 S6 提交中修订一次**（C6 两年期约需十几分钟）。S4、S5 两个中间提交上 C6 的 golden 是旧的，`p0_gate nightly` 只应在 S6 之后运行。
5. **W_in 的定义**：采用“声称的调度内弃置量，以节点未用供给为上限”，并新增 `unrealised`、`to_dispatch`、`curtailed` 三列。不加上限时，overshoot 会把不存在的盈余记作弃置，第 0 期残差变为 −60，而不是计划给出的 −18.829。
6. **physical_dispatch 不新增行、不改 scope 文案**（这些是 trajectory 列），W_in 分量记在 excess 行和削减行上。
7. **corrected 口径目前也声明 surplus node**：P0-6 的开关都还在待定集合中，两个口径都解析为 DOCTORAL 规则集。规则集到边界的映射已经就位，P0-6 启用 CORRECTED 后会自动声明 `native_corrected_full_node_v1`；部分规则集不声明边界。
