## 5 偏差

1. **gate 环境**：无法联网安装，没有建 gate venv，也没有生成带 hash 的 `requirements/value-test-py310.lock`；直接只读使用 INSTALLED 的 Python 3.10.18。指纹中 pytest/pypdf 为 null，139 个 pytest 风格测试记为 not_run。需要作者批准离线安装后补齐。
2. **隔离区语义**：按任务要求把“依赖宿主环境”的失败（49 个）放进隔离区，而不仅是两次采集不一致的 id；两次采集本身完全一致，没有 flaky。
3. **golden 第三个区 identity**：Q12 只定义了 trajectory 与 accounting；但代码/模块/上下文哈希会随任何代码改动而变，若归入前两区会让每个提交都误报。因此新增 identity 区，只报告不拦截，版本由 VERSION_LEDGER 管理。zones.json 规定不得把 Q12 的 trajectory 列改划到其他区。
4. golden 的 fast case 使用 full 账本粒度，long case 用 summary 以控制体积；所有 case 用固定 run id；哈希截为 128 位。
5. golden 两族的快速检查放在后端棘轮里（test_golden_doctoral/corrected），quick 档另跑 `capture.py validate` 做簿记，而不是单独再跑一遍 case。
6. RUNTIME_OVERLAY v2 的 kind 增加 `value_instrumentation`（计划正文提到“初始登记为 value_instrumentation”）。
7. correction id 按计划正则 `^[a-z0-9]+(\.[a-z0-9-]+)+$`，包名段不能有连字符（如 `p05.x`）。
8. `force-copperplate-balancing` 未加入旧 id 映射：运行时类仍报告该 id，映射会改变 Study 指纹，留给改名的工作包。
9. quick 档跑 9 个 node 测试文件（计划写 4 个）；ESLint 棘轮在消息减少时也要求更新基线（`--update-eslint-baseline`，只能收缩）。
10. `tests/test_preflight.py` 的磁盘敏感测试在本次采集时因磁盘空间已够并未失败，但仍按计划改为固定 `disk_usage`。
11. 离线 e2e、口径目录、能量平衡不变量、oracle 运行、golden 敏感性等 gate 步骤目前为“跳过并注明原因”，入口文件出现后自动启用。
