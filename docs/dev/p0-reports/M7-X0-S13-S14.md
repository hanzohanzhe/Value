## 2 S13 delta 报告

### 2.1 做法

`delta_report.py` 只读已提交的 golden 文件（约 1 秒，不跑模型）：

- **相对第 0 号修订的 delta**：每个 case 的最新修订与修订 0（35aadb3）逐列比较，区按 `golden.pinned_zones` 归类；每一行归到“其 delta 记录里改过这一列的那些修订”的 correction id。改过又改回的列不出现。
- **双口径 delta**：每个 doctoral case 与同数据包、同 mode、配置差异最少的 corrected case 配对（D1–C4、D2–C2、D3–C3、D4–C5；D5 是 GBP1 研究包，没有 corrected 伙伴，列为 unpaired）。两边最新 digest 逐列比较，每行归到两边改过该列的修订的 correction id；修订 0 时两边就已不同的列，另归到伪 id `profile.reference-configuration`（Q3 参考配置：legacy 储能电价、doctoral 碳因子；D2/D3 的伙伴还用了不同的储能成本模块）。它是配置差异，不是修正，报告中写明。
- **归因检查**：行没有 correction id（没有修订记录过该列，或修订只写了 finding）就列为 unattributed，`--check` 失败；未在任何地方定义的 correction id 也报错。
- correction id 的来源索引：方法学目录（带 track）、VERSION_LEDGER 的升版记录、golden 修订原因。描述与 finding 优先取目录；多个 id 共用一个修订时（D5 r1 有 12 个 id，M5 合并修订有 5 个），只取“单独记录该 id 的修订”的 finding 和原因，避免把别人的 finding 挂到它名下。

### 2.2 输出与结果

- `docs/release/P0_GOLDEN_DELTA.md`（约 23 KB，确定性、无时间戳）：第 1 节各 case 的 trajectory/accounting/identity 列数；1.1 节 correction id × case 矩阵；第 2 节四对双口径 delta 与配置差异；2.1 节归因矩阵；第 3 节 correction id 表（来源、所在 golden 族、finding、模块升版、描述）；第 4 节归因检查。`--json` 输出每一行（不提交）。
- 当前结果：13 个 case、4 对，**unattributed 0 行**，未定义 id 0 个。doctoral D1–D3 的 trajectory 列与修订 0 逐位相同；D4（426 列，A4）与 D5（377 列，A3/A5/A4）各重基线一次。corrected 族自修订 0 起 trajectory 变化列数：C1 34、C2 35、C3 50、C4 32、C5 503、C6 490、C7 34、C8 111。

## 7 偏差

1. **双口径 delta 的伪 id。** 计划要求“每一行都能归到某个 correction id”。修订 0 时就因参考配置（Q3）不同的列，不是任何修正造成的，归到伪 id `profile.reference-configuration` 并在报告中说明。这是保守做法：不把配置差异算到某个修正名下。
2. **多 id 修订的归因是按修订整体给的。** D5 r1（12 个 id）和 M5 合并修订（5 个 id）中的每一列都归到该修订的全部 id，无法细分到单个 id；报告写明了这一点。
3. **不在方法学目录中的 correction id。** p04.*、p08.*、`p06.physical-operating-cost`、`p06.staged-dwell-disclosure`、`p07.cost-ledger-v2` 只登记在 VERSION_LEDGER 或 golden 修订中。delta 报告从三处建立索引，并标出来源；没有把它们补进目录，因为那会改变方法学目录哈希和各口径的 applied-corrections 哈希，进而触发 Study 迁移。
4. **delta 报告提交为 Markdown 摘要，不提交逐行 JSON。** 逐行结果约数 MB，用 `--json` 按需生成。
5. **METHODOLOGY_PROFILES 的生成放进已有的 `generate_reference_tables.py`**，没有另写脚本，这样既有测试和 full 档步骤直接覆盖它。
6. **README 只加一句版本说明**，没有改动下载链接：链接指向的 Full 批次仍是 0.6.0-alpha.2，README 中已写明。
7. **CITATION.cff 未改。** 它的 `version` 是源码快照 id `source-2026-10-04`（与 source-release-manifest 的 `snapshot_id` 一致），不是应用版本；改它属于发布快照，留到 M8。
8. **`model-sdk/contracts.ts` 未改**（计划 2.4 节把它列在 S14 的 API 契约汇总中）。本单元只在 EXPANDED_FRONTEND_CONTRACT 中指向 CHANGELOG 的变更表；TS 契约同步留给前端或集成者。
