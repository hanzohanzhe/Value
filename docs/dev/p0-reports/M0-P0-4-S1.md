## 2 实现要点

### 2.1 契约（`gridform_core/energy_balance_contract.py`，只依赖 math/dataclasses/typing）

- 边界：`full_node_v1`（r = S+B−D−C−E−X）、`default_psm_surplus_node_v1`（r = S+B+U_out−W_in−D−C−E−X，Q7；U_out、W_in 来自 S5 才会新增的可选表 `surplus_routing`，按 source_class=in_dispatch/out_of_dispatch 分行，另有逐行盈余守恒）、`retained_demand_serving_v1`（HEAD 内核的 raw 口径，只作诊断分解，`verdict_basis=False`）。
- 容差两档：exact_arithmetic abs 1e-6 / rel 1e-9；lp_solver abs 1e-5 / rel 1e-7；年度 Σ|adj|/ΣD 上限 1e-6。
- `BOUNDARY_REGISTRY` 的键为 (module_id, 版本区间, rule_set)（C19）。目前登记：`value-bid-at-cost-psm` [0, 6.0.0) 且 rule_set ∈ {未记录, doctoral-lineage-0.6.0a2} → surplus_node（raw 列旧口径为 retained）；PF LP、staged、DC → full_node。P0-6 以后追加 `native_corrected_full_node_v1`。
- 包络必要条件：−(C+E+X) − tol ≤ full_node ≤ XS + K + tol。
- **A2 stress 项**（两口径通用，只作报告量）：逐期缺口 shortfall = max(0, D + C+E+X − U_out + W_in − S)；有 routing 时精确，否则给出区间 [max(0, D−S), max(0, D + C+E+X + min(XS+K, S) − S)]；同一年内连续的缺口时段合并为一个 event；年度汇总给出 stress_periods、event_count、缺口上下界、已记录的 blackout 与隐藏缺口下界。

### 2.2 oracle（`gridform_core/energy_balance_oracle.py`）

- `mode=ro&immutable=1` 打开，另加 `PRAGMA query_only=ON`；读前读后各算一次 sha256 写入报告（`ledger.sha256_before/after/unchanged`），读期间变化则判 not_evaluated。
- 非空 `-wal` / `-journal` → not_evaluated（`GF_ENERGY_BALANCE_UNCHECKPOINTED_WAL`）。
- 边界确定顺序：metadata（`energy_balance_boundary`，S6 起由内核写入）→ 注册表 → unknown。
- **只有在 metadata 中声明了边界且所需输入齐全时才可能 passed**；没有声明的旧账本只做包络必要条件：越界判 failed，否则 not_evaluated，永不 passed。
- 检查项都带 class（independent / integrity），报告给出 full_node、retained、声明边界残差的序列统计，自报值（raw、adj、residual）的一致性，Σ|adj| 与 ΣD 之比，以及 A2 stress 段（`shortfall_mwh` 只在精确时给值，否则为 null 并给出上下界、`stress_periods`、`event_count`、逐期与逐事件明细）。
- CLI：`python -B -m gridform_core.energy_balance_oracle <market.sqlite | run 目录> [--output f] [--quiet]`，退出码 0 passed、1 failed、2 not_evaluated、3 用法或输入错误（argparse 默认的 2 被改为 3，避免与 not_evaluated 混淆）。

## 5 与计划的偏差

1. **包络上界取 XS+K 而不是计划中的「excess」**：默认 PSM 把被削减的核电必发出力留在 S 中并记在 `curtailed_mwh`，nuclear_curtail 夹具（门禁期望 not_evaluated）在削减时段的 full_node 等于 XS+K；只用 XS 会把这个没有已知缺陷的夹具误判为 failed。overshoot、nuclear_balancing 的判定不受影响。
2. **nuclear_balancing 的调整期数**：计划中写「21/48 期被兼容调整掩盖」，按评审给出的 pack_nucbal 参数（29 MW、预测低 6 MW）在 HEAD 上实测为 35/48 期（其中越包络 35 期，最大越界正好 3.000）。评审原夹具的其他细节无从还原，以实测为准。
3. **overshoot 的 Σ|adj|**：计划写 819.40 MWh，实测 810.546 MWh（ΣD = 775.491 与计划的 775.49 一致，第 0 期 −18.829 一致，48/48 期一致）。结论「Σ|adj| 大于 ΣD」不变。差额来源无法从计划文本还原，测试按实测值固定。
4. **CLI 退出码 3**：计划只规定 0/1/2；用法或输入错误另用 3，避免 argparse 默认的 2 被误读为 not_evaluated。
5. **golden 格式**：计划文件名照旧（`scripts/p04_capture_trajectory_golden.py`、`tests/fixtures/p04_trajectory_golden.json`），但内容按 C17 复用 golden.py 的「表×列」摘要，而不是另起一套编码。
6. **多 stage 账本**：计划未提及。oracle 每个 (year, period) 只取 `final_dispatch` 行，仍有歧义时判 not_evaluated（保守处理）。
