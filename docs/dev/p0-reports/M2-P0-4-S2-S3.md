## 2 实现要点

### 2.1 S2：每条结论都追溯到执行过的检查（P7-01）

- **`gridform_core/run_invariants.py`（新）**。每项检查带 `class`（independent / cross_path / integrity）和 `severity`（本单元一律 `report`，P0-4 S7 改为 gate）：
  - `run.period_coverage`（integrity）：账本中每年的时段数（同一时段多个 stage 时只取 `final_dispatch`，与 oracle 同一规则）和 typed 结果的时段数都等于 periods_per_year。
  - `run.demand_input_reconciliation`（cross_path）：`input_factory` 构造 chronology 时把 ΣD、ΣF 与时段数写入 `validation/input-tally/year-<Y>.json`（续跑后仍可读到早年的 tally），之后与账本 `period_summary` 和 typed `total_demand_mwh` 比较，容差为 exact 档（abs 1e-6，rel 1e-9）。retained 内核自己读源文件，所以这是两条读取路径的交叉核对。使用网络包时 PSM 可能以分区需求为准，记为 `GF_INVARIANT_DEMAND_AUTHORITY_NOT_CHRONOLOGY`（not_evaluated），不硬比。
  - `run.generation_cross_path`（cross_path）：typed `generation_mwh_by_asset` 逐资产对账本 `physical_dispatch` 的 generation/import（typed 中出现的储能资产再加 storage_discharge，这是 PF LP 的约定）；同时核对 typed 总发电量等于逐资产之和。summary 级账本没有逐资产行时为 not_evaluated。
  - `run.state_chain`（integrity）：上一年 `next_state` 的哈希等于下一年的 `annual_input_state_sha256`；启用网络扩张时改为核对“上一年输出 = network advance 事件输入”与“network advance 输出 = 年度输入”；并核对 transition 与 planning advance 事件里的哈希。PSM-only 运行记为 not_applicable。
  - 汇总规则：任一失败即 failed；所有适用检查都通过、且至少有一项 independent/cross_path 检查执行过才是 passed；否则 not_evaluated。UI 计数（`checks_passed/checks_total`）只统计 independent 与 cross_path，integrity 另计。
  - 只读：`mode=ro&immutable=1`；账本旁有非空 `-wal`/`-journal` 时不读（`GF_INVARIANT_LEDGER_UNCHECKPOINTED_WAL`），因为 immutable 会忽略 WAL 中的行。
- **stage parity v3（`parity.py`）**。`build_native_parity_report` 取代 application 中写死的 v2 字面量，记录实际执行的合同检查：typed 年份、每年核心阶段顺序（取最后一次 planning.advance 之后的序列，兼容取消后重算的年份）、账本行数对 metadata、年度成本账“计入行之和 = cem_system_cost”。每行带 actual/expected/absolute_tolerance，可被复算。没有执行任何检查时 `contract_parity_passed=None`。能量平衡与 run 不变量作为 report 级证据附在报告里，不参与 `contract_parity_passed`。旧路径 `compare_run_bundle` 删去“调整后残差恒为 0”的检查，改为委托 oracle。
- **oracle 辅助（`energy_balance_oracle.py`）**：`evaluate_run_ledger`（没有账本时 not_evaluated，不抛异常）与 `stored_report`（绝对路径换成 bundle 内相对路径，账本哈希记为 `source_artifact_sha256`，stress 逐期与事件列表设上限并记录总数），写入 `validation/energy-balance-oracle.json`。
- **scientific validation v2（`scientific_validation.py`）**：
  - `contract_validation_status` 由 parity 行复算：只有 `{'contract_parity_passed': True}` 时为 not_evaluated（`GF_VALIDATION_CONTRACT_NOT_EXECUTED`），P7-01 的复现调用因此不再得到 passed；行的 `pass` 与复算不符、或顶层标志与各行不符，判 failed（`GF_VALIDATION_CONTRACT_SELF_INCONSISTENT`）；缺值的行判 failed（`…_CHECK_MALFORMED`）。
  - `run_invariant_status`、`energy_balance_status` 按各自报告的检查行复算，不信任其顶层字段。
  - `stress`（A2）：`stress_periods`、`event_count`、`shortfall_mwh`（只在 stress 时段上求和的“确定缺口”：有 surplus routing 时精确，否则是“需求减去已接纳供给”的下界，`shortfall_basis='lower_bound'`）、`shortfall_upper_mwh`、按年汇总。
  - `raw_invariants`（Q14 证据）：两者都 passed 才 passed，任一 failed 即 failed。
  - `validation_warnings`：合同失败或未评估、run 不变量失败、能量平衡失败或未评估、存在兼容调整、存在 stress 事件。
  - `analytical_mechanism_status` 保留原名，并新增别名 `module_self_test_status` 与说明（固定夹具的自检，与本次运行的数值无关）。PSM-only 课程不运行自检，记为 not_evaluated。
  - 能量平衡和 run 不变量在 S7 之前只报告，不改变 `scientific_validation_status`，也不阻止年度结果发布（计划 S7 与附表 P0-4 Q5）。
- **application.py**：年度路径与 PSM-only 路径都经 `_write_validation_artifacts`：oracle → run 不变量 → parity v3 → v2 报告。两处写死的 passed 都已删除。
- **bundle_validator.py**：v2 bundle 必须带 parity、run-invariants、oracle 三个证据文件，且报告中的三个状态必须等于由这些文件复算的结果（`GF_BUNDLE_VALIDATION_STATUS_MISMATCH`）。v1 bundle 不受影响（由读时 advisory 处理）。

- **model_runner**：把 v2 报告的 `run_invariant_status`、`run_invariants`、`energy_balance_status`、`energy_balance`、`stress`、`raw_invariants`、`validation_warnings` 写入 run status。

  - Q14 的 `raw_invariants_status` 改用同一份证据：只有 v2 报告能给出 passed；status.json 里单独的副本不被采信（避免手改 status 就能发布 doctoral 年度结果）。

- **market_replay**：窗口内残差与兼容调整改为 `SUM(ABS(...))`（`residual_aggregation='sum_of_absolute_period_values'`）；每个窗口新增 `stress_periods`、`possible_stress_periods`、`shortfall_mwh`、`shortfall_upper_mwh`、`shortfall_basis`，按与 oracle 相同的契约逐期计算（多 stage 只取 final_dispatch；有 surplus_routing 表时精确）。
- **server.list_runs**：新增一行 `compact_validation_fields(row)`，列表只保留能量平衡徽章和 stress 计数，其余证据留给 `/api/runs/<id>`。

## 5 偏差

1. **run 不变量与能量平衡不进入 gate**：严格按计划把 gate 留给 S7。代价是 S7 之前，run 不变量失败的 Run 仍可能显示 `scientific_validation_status=passed`；它会在 `run_invariant_status`、`validation_warnings` 和比较审查原因中出现。
2. **`shortfall_mwh` 在缺少 surplus routing 时给下界**：oracle 自身的 `stress.shortfall_mwh` 只在精确时给值；面向 UI 的字段（status、summary、replay）改给“确定缺口”下界并标 `shortfall_basis='lower_bound'`，与设计规格示例（r2：570.5 MWh、48 periods）一致。前端目前只读 `shortfall_mwh`/`stress_periods`，没有显示 basis，请设计方决定是否在 `lower_bound` 时加“≥”或说明（建议写入 P0_FRONTEND_DEVIATIONS，本单元未改前端）。
3. **有口径记录的旧 v1 报告也改为 superseded_pre_fix**：X0 S10b 只覆盖没有口径的 Run；本单元把规则扩展到“依据非 v2 报告的 passed”，因为 X0 S9 之后产生的 v1 报告同样写死了合同 passed。相应更新了 `test_server_presentation`、`test_result_advisories` 与 `P0_CONVENTIONS`。
4. **Q14 证据只认 v2 报告**：X0 的契约原来也接受 status 中的字段；改为 status 副本单独存在时不采信。
5. **改了 `server.py` 一行**（`list_runs` 调用 `compact_validation_fields`）：计划 S3 写“不再改 server.py”，指的是 present_run 的科学状态逻辑（C7），该逻辑未动；列表瘦身只能在 list_runs 处做，否则超出列表大小上限。
6. **列表大小测试放宽到 2,500 字节**（见第 3 节）。
7. **parity v3 的合同检查范围**：评审建议的 (b) 成本闭合、(c) 状态衔接、(d) 时段数已实现（后两者在 run 不变量中）；(a) 原始残差门限属于能量平衡（S6/S7），(e) 失负荷比例告警未单独实现（stress 汇总已给出缺口与 recorded unserved）。
8. **网络包运行的需求核对记为 not_evaluated**：分区需求模式下 PSM 的需求来源不是 chronology，未做硬比，以免误报。
9. **commit 方式**：为了逐提交跑门禁又不丢弃工作树的改动，先在 scratch 临时 worktree 中依次提交，再快进集成分支（内容与在 INTEG 中直接提交相同）。
