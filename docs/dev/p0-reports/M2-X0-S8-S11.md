## 5 偏差

1. profiles.json 比计划多两个字段：`supported_extensions`（扩展没有 scientific_version，不宜混入 supported_modules）和 `result_publication`（Q14 规则）。两者都进入 `profile_definition_sha256`。
2. 分类与迁移逻辑放在新文件 `gridform_core/revision_migration.py`；`project_revision.py` 只加 basis、reason 与 payload 的重建参数。
3. 新增 `data_changed` 类别（同 id 数据包内容变化）：Q13 要求数值变化须确认，计划的类别里没有对应项。
4. `unverifiable` 在预检中仍是错误，但允许通过迁移接口确认后重新建立 basis；否则这类 Study 永远无法再运行。
5. 修订身份加入口径 identity。结果：S11 之前保存的每个 Study，在本分支上第一次运行前都需要用户确认一次（重建出 35aadb3 basis 后归为“口径首次写入”）。这是 Q13 的直接要求，但影响面大，请作者知悉；重装后 VALUE 101 和研究 Study 各需确认一次。
6. 修复前 Run 的 `contract_validation_status` 也按正向声明覆盖为 superseded_pre_fix（P7-01 指出 v1 合同 passed 是写死的）。
7. S9 没有把口径写进 `scientific-validation.json`：该报告在 golden 的 reporting 节中，新增列会在 doctoral 族被当作未批准的 trajectory 变化；status/provenance/resolved-run 已完整记录口径。
8. pack_class 判定暂由 `methodology.classify_data_pack` 提供（manifest 字段 → 已知包表 → teaching_only → SYNTHETIC → user_workspace），P0-5 S3 接管。GBP1 的白名单同时接受 manifest 文件字节与规范 JSON 两种 sha，以免安装时重新序列化导致误拒。
9. 静态扫描白名单：`energy_balance_contract.py`（P0-4 的 `BOUNDARY_REGISTRY` 以规则集 id 为键，待 P0-4 S6 改为从口径推导）和 `scripts/capture_p0_5_baseline.py`（M0 采集脚本）。

11. S10a 的 `_read_object` 读不出验证报告时不再向 stderr 打印 `read_json` 的提示，返回值不变。
