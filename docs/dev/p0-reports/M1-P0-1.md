## 2 各步骤要点

### S1 会话令牌与工厂
- 令牌 `secrets.token_urlsafe(32)`，后端 bind 之后写 `<VALUE_DATA_HOME>/runtime/api-session-<实际端口>.json`：目录 0700（已存在时也收紧），临时文件 `O_EXCL|O_CREAT` 0600 写入并 fsync，再 `os.replace`；写失败不留残片。只有文件中的令牌仍属于本进程时才删除。
- `make_api_server(host, port, *, session_token, data_workbench_api=None)`：只允许 127.0.0.1/localhost；不触碰任何 state 根目录；workbench 只在传入时挂载。
- 就绪行改为 `VALUE modular API: http://<host>:<实际端口> (session file <路径>)`，令牌从不出现在 stdout、命令行或环境变量中。
- `--port 0` 也可用（测试用）。

### S2 测试夹具
- `start_local_api(data_home=…)` 返回 `(httpd, origin, token)`，发布会话文件，opener 只为本服务的 netloc 补 `X-VALUE-Session`。需要保留自身 state 根选择的旧测试用 `patch_state_roots=False` + `start()/stop()`（此时不发布会话文件、不挂 workbench，与原行为一致）。
- 迁移脚本按字节替换，保留每个文件原有的 CRLF/LF 混合行尾。

### S3 网关
- 所有请求：Host 必须精确为 `127.0.0.1:<端口>` 或 `localhost:<端口>`（端口每次请求从 socket 读取），否则 421；页面请求的 421 返回与规格同文案的静态 HTML，`/api` 请求返回 JSON。所有响应加 XFO DENY、nosniff、Referrer-Policy、COOP/CORP、Permissions-Policy。
- 页面：每次响应一个 nonce，写入 CSP 响应头并写入请求头 `content-security-policy` 供 vinext 读取；`VALUE_UI_CSP_REPORT_ONLY=1` 为应急开关。
- `/api`：只放行 GET/POST/OPTIONS；`Sec-Fetch-Site` 存在时只接受 same-origin/none；POST 的 Origin 必须等于 `http://<Host>`，必须有 Content-Length（否则 411）；去掉逐跳头、Origin/Referer/Cookie/Sec-Fetch-* 与客户端自带的会话头，注入令牌后流式转发；回程删除 `Access-Control-*`；被拒且请求体 ≤2 MiB 时先读完再答（避免 RST），更大则答后关闭。API 返回 403 `GF_SESSION_*` 时改写为 502 `GF_GATEWAY_SESSION_MISMATCH`（给出会话文件路径）；会话文件缺失 502 `GF_GATEWAY_SESSION_UNAVAILABLE`；上游不通 502 `GF_GATEWAY_UPSTREAM_UNAVAILABLE`。
- `serve-value-ui.mjs`：`--host` 只接受回环；`--api-origin` 必须是带端口的 http 回环源（默认 `http://127.0.0.1:8766`）；在 vinext listen 回调的同一宏任务内包装监听器，并断言监听器恰好 1 个。数据目录解析与 `runtime_paths.user_data_root()` 一致（空串视为未设、`~` 展开、相对路径按 cwd 并告警、符号链接按 Python `resolve()` 解析）。

### S6 后端守卫
- `evaluate(method, path, headers, *, bound_port, token)` 纯函数，顺序：Host（421，重复 Host 也拒）→ 任何 Origin（403 `GF_BROWSER_ORIGIN_REJECTED`）→ Sec-Fetch-Site≠none（403 `GF_BROWSER_CONTEXT_REJECTED`）→ Content-Length 非十进制（400）、POST 带 Transfer-Encoding（411）→ 会话（403 `GF_SESSION_REQUIRED`/`GF_SESSION_INVALID`；只有不带该头的 `GET /api/health` 与 `OPTIONS` 免令牌；带了错误令牌的 health 也拒，便于网关发现不匹配）→ POST Content-Type 缺失或为简单类型（415，按原始头判断）。
- `_guard()` 返回 bool，`_dispatch` 写作 `if self._guard(): route()`，因而五个绕过 `_json_body` 的上传路由同样受保护。`end_headers` 为每个响应（含 `send_error`）加 nosniff、`X-Frame-Options: DENY`、`CSP default-src 'none'`、Referrer-Policy、CORP；带 `error_code` 的错误响应加 `X-VALUE-Error-Code`。
- 删除 `ALLOWED_ORIGINS`、`_origin()` 和所有 `Access-Control-*`。CSV 比较结果改为附件（`value-run-comparison.csv`）。
- 无令牌 health 只返回 `{ok, service, version, python, authoritative_runtime_compatible, session_required, status, degraded_reasons}`；`status`/`degraded_reasons` 暂由 `health_degradation()` 返回 `"ok"`/`[]`，留给 P0-2 填充。

### S7 浏览器级回归与探针
- `e2e/security-boundary.spec.ts`：真实攻击服务 127.0.0.1:18999，分别以 `http://127.0.0.1:18999`（same-site）和 `http://localhost:18999`（cross-site）访问；no-cors text/plain fetch、text/plain 与 urlencoded 表单、跨源读取、JSON 写入、iframe。状态码从 CDP `responseReceivedExtraInfo` 原始响应头读取（被拒的 no-cors 响应因 CORP、跨源读取因无 CORS 授权，页面拿不到响应，Playwright 自己的 response 事件可能不触发）；所有到达 VALUE 的请求必须是 403/421；没有拿到任何应答就失败的请求判失败；攻击后没有新数据包；iframe 中看不到 VALUE。阳性对照：同一写入经页面路径 201、去掉页面 Origin 403、直连 API 403。13 个视图 CSP 违规为 0。
- `scripts/verify_local_security_boundary.py`：18 个探测（API 12 个、网关 6 个），每个都是必须被拒、且即使被接受也不改变任何东西的请求（只校验的路由、不存在的 Run 的 mark-lost、P0-2 的 rescan 带 `X-VALUE-Acknowledge-Pending-Runs`、不带信任头的空模块上传），另检查无 CORS、安全头和页面 CSP；从不发送令牌。退出码 0/1/2。
