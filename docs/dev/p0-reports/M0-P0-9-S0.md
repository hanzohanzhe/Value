## 3 做了什么

### 3.1 S0 离线 e2e（`977c905`）

- `e2e/start-e2e-services.mjs`
  - 数据包和示例模块只在存在时复制，缺失时打印 `VALUE_E2E_SKIP_COPY missing …`，不再因为 force-castle-101-v1 不存在而抛 ENOENT。
  - 非 Windows 默认解释器改为 `python3`，`VALUE_PYTHON` 仍可覆盖。
- `e2e/run-tests.mjs`
  - 所有参数透传给 `playwright test`。
  - 新增 `VALUE_E2E_SKIP_BUILD`、`VALUE_E2E_JSON`、`VALUE_E2E_OUTPUT_DIR`。
  - `--offline`：强制 `VALUE_E2E_UI_ONLY=1`，只跑 `e2e/offline-subset.json` 中的 7 个 spec，再用 `e2e/offline-ratchet.mjs` 判定结果，退出码由棘轮决定。
- `e2e/offline-ratchet.mjs` 的判定规则（与后端棘轮一致）：
  - 测试 id 用“文件 > 标题路径”，不用行号；
  - 未登记的失败判失败；
  - 已登记的失败转为通过时，必须从登记表删除；
  - 登记的测试没有运行、某个 spec 没有产出结果、通过数低于 `min_passed`，都判失败；
  - 新增 `error_must_match`：已登记的失败必须且只能因为登记的那个断言失败。这样一个为某个断言登记的测试，不能掩盖第二处损坏。
- `playwright.config.ts`
  - `VALUE_E2E_CHROMIUM` 可指定浏览器可执行文件（兼容 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`）。本机锁定的 Playwright 需要 headless_shell-1228，缓存里只有 1243，必须用这个钩子。
  - 可选 JSON 报告和输出目录。
  - `tests/frontend` 的两个浏览器 harness 通过 `tests/frontend/helpers/chromium.mjs` 共用同一个变量，旧变量 `CSV_MAPPING_CHROMIUM_EXECUTABLE` 仍然有效。

  - expanded-workflows:188：通过链接 `?study=…&run=…` 打开 Run，删除已经移除的 AC 页签断言（前端 guard 禁止 AC 页签回归）。
  - network-redispatch:697：按精确可访问名称定位侧栏的“Runs: Launch and compare”。
  - market-visibility：见第 4 节偏差 1。

  - `VALUE_E2E_CHROMIUM` 未设置时 skip（非强制步骤），路径不存在时判 failed。

### 3.2 S0 单元测试基础设施（`a81ae11`）

- `scripts/run-ui-tests.mjs` 与 npm 脚本：
  - `test:ui-unit`：`tests/frontend/unit`，纯视图逻辑；
  - `test:ui-render`：`tests/frontend/render`，esbuild 加 `renderToStaticMarkup`，不需要浏览器；

- `tsconfig.json`：开启 `allowImportingTsExtensions`（tsconfig 已有 `noEmit: true`）。开启后 tsc、ESLint、vinext build 和 `node --test` 都通过。按计划，回滚时须与 S1 一起回滚。

  - vre-timeline（daily，limit 500）；
  - periods（limit 50）；
  - storage；
  - 首个 ahead、balancing、curtailment 时段的 auction。

  - `toy-v8`：用 `create_staged_market_ledger_v8` 在 summary 级 trace（VALUE-UK 的默认值）下写 4 个时段、两个区。dispatch_summary 使用 staged 写入方记录的原始技术名（CCGT 同时出现在两个区，另有 onshore、battery、interconnector）。

## 4 偏差（Deviations）

1. **market-visibility 不是 1/1。** 计划 S0 的验收写的是 market-visibility 1/1，本次任务说明允许它在 M2 之前只因 R3-01 的价格断言失败。我按审查报告 R3-01 的修改建议 (d) 修了 spec：
   - mock 改用 API 真实发送的字段 `price_gbp_per_mwh`，取值 61.25 起，不与任何报价重复，并补上 `price_aggregation` 和 `period_hours`；
   - 新增一条 soft 断言，范围限定在 `.selected-period-strip`。
   - 结果：该 spec 目前 0/1，失败只有这一条 soft 断言，其余断言（merit order、VRE 页、axe 扫描）全部执行并通过。这一点由 `error_must_match` 强制。S3 修好之后，棘轮会要求删除这条登记。
   - 不这样改的话，测试会靠 merit order 表里的 £50 显示为绿，等于继续掩盖 R3-01。这是两种做法里更保守的一种。
2. **expanded-workflows:103 和 :118 登记为已知失败（owner P1）。** 计划只列出 :188 需要修。这两条是 UI 按设计改动后留下的过时 spec，不属于本包依赖的 spec；按“只修本包依赖的 spec”处理，没有改写它们。计划中“其余 4/4”的含义不明确；本次实测其余各 spec 的结果是：expanded-workflows 1 通过、2 已登记；result-queries 2/2；comparison-review 1/1；evidence-isolation 1/1；castle-101 在 UI-only 下 4 条全部 skip。
3. **network-redispatch 的计数。** 当前文件共有 22 个测试（有两处 for 循环生成的测试），实测 19 通过、3 个已登记失败。计划写的“≥16/19”是旧计数；`min_passed` 设为 19，比计划更严。原 :710 现在位于 :712，因为 :697 的修正多了 2 行注释。
4. **7 个离线 spec 的选择。** 计划没有逐一列名。选了 market-visibility、network-redispatch、expanded-workflows、castle-101，以及 result-queries、comparison-review、evidence-isolation：后三个都完全用 route mock，并且自带 UI-only 配置。castle-101 需要真实服务，在 UI-only 下 skip（计划要求的是缺包时 skip，这里多了一个 UI-only 条件，并写明了原因）。
5. **S2 只做到生成器、夹具和 Python 测试。** `marketTypes.ts`、编译期穷举和 ui-contract-keys 这些 TS 侧内容不在 M0。真实 Run 使用 golden C3 的冻结项目，而不是会变的课程模板，这样夹具不会随模板漂移。
6. **没有生成 run summary / status.json 夹具。** `build_run_summary` 依赖 model_runner 写出的 `status.json`，`run_project_application` 不产出这个文件。S5/S9 需要时再扩展生成器（见第 6 节）。
