## 7 偏差

1. **没有追加新的 golden 修订**。计划写的是“S10 对 corrected 族做一次统一重基线”。但 M5 合并时已经在合并后的代码上为 P0-5b 和 P0-7 各记了一个修订，本单元的 exact 重跑与之逐列相同；golden 库也拒绝不改变 digest 的修订。因此 S10 以“exact 重跑确认 + 归因检查 + 验收记录”完成，这是更保守的做法。
2. **归因粒度为修订，而不是单列**。P0-7 的五个 id 在合并时记成一个修订（`M5-merge.md` 偏差 1）。投资路径的变化会连锁影响规划、终态与碳账等许多列，按列拆到单个 id 需要构造中间状态逐个重跑，用户要求迅速推进，所以没有做。lane 分支 `fix/review-2026-10-04--m5-inv` 的历史中保存了分步修订。
3. **验收记录是快照**。`tests/fixtures/p07/s10_acceptance.json` 由本次运行生成；测试只要求它指向已存在的 golden 修订，所以以后的里程碑追加修订不会让测试失败。如果要重新验收，用第 9 节的命令重新生成。
4. **没有做双口径的逐列数值对比**（corrected 对 doctoral）。两族之间的差异还包含 P0-4、P0-6 的全部口径修正，以及参考配置的不同（doctoral 碳因子情景），这些都是 X0 S13（M7）双口径 delta 报告的工作。本单元的“delta 报告”指 M5 引入的变化。
5. 只跑了 `p0_gate quick`（用户要求）。
