# Security policy

VALUE is a loopback-only local research application. Report suspected path
traversal, unsafe archive import, checkpoint code execution, cross-site or
DNS-rebinding access to the local services, credential exposure or unintended
network binding privately to project owner Hanzhe Xing through the
repository's [private security-advisory form](https://github.com/hanzohanzhe/Value/security/advisories/new).
Do not open a public issue containing exploit details.

The maintainer aims to acknowledge a report within five working days, complete
initial severity and reachability triage within ten working days, and provide a
status update at least every fourteen days until resolution. A coordinated
disclosure date will be agreed with the reporter. These are response targets,
not a promise that every scientific or availability defect is a security issue.

## Local access boundary

VALUE runs two loopback services: the web interface (UI, port 8800) and the
model API (port 8766). Any web page you open can address loopback, so the
boundary does not rely on "loopback only":

- The browser talks only to the UI origin. The UI gateway answers only
  requests addressed to `127.0.0.1:<port>` or `localhost:<port>` (421
  otherwise, which defeats DNS rebinding), refuses `/api` requests from other
  sites (`Sec-Fetch-Site`, and for writes an `Origin` equal to the page's
  own), sends a per-response Content-Security-Policy with a script nonce,
  `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, and forwards
  `/api` requests to the API with the session token it holds.
- The API checks the `Host` header, refuses every request that carries a
  browser `Origin` or a cross-site `Sec-Fetch-Site`, requires the per-process
  session token (`X-VALUE-Session`) on every route except a reduced
  `GET /api/health`, refuses form-style bodies (`text/plain`,
  `application/x-www-form-urlencoded`, `multipart/form-data`, or no
  `Content-Type`) with 415, and sends no CORS headers at all.
- The session token is generated by the API at start-up and written only to
  `<VALUE_DATA_HOME>/runtime/api-session-<port>.json` (directory 0700, file
  0600). Launchers never see it; it is not on any command line, in any log,
  in worker environments, exports, archived workspaces or diagnostics, and
  it is never sent to the browser.
- Scripts that call the API directly read the token with
  `backend.api_session.authorized_headers(<data home>, <port>)` and must not
  send an `Origin` header. Alternatively they call the UI origin
  (`http://127.0.0.1:8800/api/...`); writes there need
  `Origin: http://127.0.0.1:8800`.
- `scripts/verify_local_security_boundary.py` probes a running installation
  with requests the boundary must refuse (and which change nothing if
  accepted). Run it after installing or upgrading.

### Single-user host assumption

VALUE assumes one person per computer. The boundary stops other web sites,
not other programs or other operating-system users on the same machine: any
local process that can read the session file, or that can connect to the UI
port, has the user's full VALUE access, including installing executable
modules. Do not install VALUE on shared laboratory computers, remote-desktop
(RDS/terminal) servers or multi-user hosts. There is no login in this release.

### What is not a security control

`X-VALUE-Executable-Trust: acknowledged` records that the user confirmed, in
the UI, that a module bundle contains trusted executable Python. It is an
informed-consent flag, not an access control.

Archived workspaces (`scripts/prepare_archived_workspace.py`) run the archived
source of an earlier VALUE version. Its API may predate this boundary; while an
archived workspace is running, do not browse untrusted web sites.

## Executable and data content

Imported run bundles are data only. Python, scripts, native binaries and pickle
checkpoints are prohibited in portable bundles. Legacy pickle checkpoints are
trusted-local compatibility artifacts and must never be imported from shared
archives.

External model-module ZIPs contain executable Python. Their conformance checks
do not provide an operating-system sandbox; install only code whose source and
publisher you trust. Data bundles are governed by a separate non-executable
contract and reject Python, scripts, native binaries, links and nested archives.

The beta is distributed with deterministic source/data archive SHA-256 values
and CycloneDX-style SBOMs. It is not cryptographically signed. Verify published
hashes before offline transfer. See `docs/SECURITY_AND_SUPPLY_CHAIN.md` for the
dependency, install-script, offline-wheelhouse and signing decisions.
